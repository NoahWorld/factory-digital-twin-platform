## 流体和工艺改进

- 钢液：直立钢包底部出钢，经保护套管进入中间包；采用耐火衬、渣面、浸入式水口和液面余量。四条铸流是方形截面、弧形辊道与凝固坯壳；二冷细滴朝向铸坯，回水进入沟槽。
- 水务：混凝土池壁、步道与检修桥采用实体材质，局部开口观察水深；曝气池、二沉池和清水池具有不同水色与波幅。圆形液面使用径向细分，刮泥桥低速运行，配水跌流使用连续水幕。
- 循环水：塔内分成布水、填料水膜、落水和集水区域，一格塔体及换热器局部剖开；换热器管壳两侧保持几何分隔，冷却水与工艺流体各有供回路径。补水、排污及旁滤具有独立去向。
- 表面细节：嵌入程序化混凝土/金属纹理和水面法线贴图；液面包含位置与法线 morph 动画。普通水体无自发光，大颗发光球改为细滴或连续水膜。自由落流截面随重力加速收缩，滴流在零尺寸处复位，避免倒飞。

工艺参考：[伊利诺伊大学连铸简介](https://ccc.illinois.edu/introduction/concast.html)用于钢包—中间包—结晶器工艺关系；[美国 EPA 污水处理基础](https://www.epa.gov/sites/default/files/2015-09/documents/primer.pdf)用于水线、沉淀及污泥去向；[美国能源部冷却塔用水管理](https://www.energy.gov/cmei/femp/best-management-practice-10-cooling-tower-management)用于补水、蒸发、排污、飘水与浓缩倍数的关系。这些资料不构成本案例的工程设计或设备选型依据。

## 模拟参数与边界

模型播放标准 glTF 动画，由平台现有浏览器运行层渲染。它们是工艺可视化案例，并非 CFD、工程校核或真实生产接入。动画按预设循环播放，模拟指标通过正式采集链路进入设备详情；当前没有指标驱动的液面、流速或热交换动画。固定卡片和图表为工况示例。

模拟数据中保留可核对的关系：

- 连铸：四流二冷水量相加得到循环水量；钢流量按 0.38 × 0.38 m 截面、各流拉速和 7.1 t/m³ 示例密度计算。包内钢量是示例工况，未实现炉次质量随时间积分。
- 水务：进水平均分至两列，污泥回流比为 50%；表面水力负荷按净前向流量及模型 13.5 m 液面直径计算；总风量为两列之和。回用水量扣除湿泥外运体积，是简化水量账，不含完整污泥固体平衡或水质动力学。
- 循环水：热负荷按循环量、供回温差、密度 1000 kg/m³、比热 4180 J/(kg·K) 计算；两负载按 55% / 45% 分担；蒸发采用全部热量以潜热排出的简化近似（2440 kJ/kg），不是当地气象条件下的预测。按浓缩倍数 4 计算排污，并满足补水 = 蒸发 + 排污 + 飘水；旁滤回到循环系统，不计为损失。

## 可复现维护

在仓库根目录操作，要求本地 Java 后端、管理员和前端已经启动：

```bash
# 重新制作模型时才执行。
node scripts/generate-fluid-cases-v2.mjs

# 演示源与 dev:mock 互斥使用本机 8790。
docker compose -f deploy/local/fluid-demo.yml up -d --wait
# 修改模拟源代码后重载。
docker compose -f deploy/local/fluid-demo.yml restart source

# 原地更新初版日志明确记录的三个案例，保留项目 ID。
node scripts/update-fluid-cases-v2.mjs
# 核对持久化资源、动画检查信息与下载哈希。
node scripts/update-fluid-cases-v2.mjs --verify-only

# 真实浏览器与模型动画验收。
PLAYWRIGHT_MODULE_PATH=/path/to/playwright/index.mjs \
CHROMIUM_EXECUTABLE=/path/to/chromium \
node scripts/verify-fluid-cases-v2.mjs
```

更新器依赖本机已有 `deploy/local/.local/fluid-cases-v1.json`，不能当作在任意平台创建项目的通用导入器。它会先保存原场景、看板、项目和资产映射快照，再写入新版，记录在 `deploy/local/.local/fluid-cases-v2.json`。初版备份为同目录 `fluid-*-before-v2.json`；这些文件被忽略提交。资源哈希不符、缺失日志、API 报错或场景/看板 revision 被外部修改时会中止，不静默覆盖。

源仍由本地受限容器提供 `/fluid/steel`、`/fluid/water`、`/fluid/cooling`，后端允许来源为 `http://host.docker.internal:8790`。每 2 秒采集，10 秒判陈旧；源停止时运行态必须显示真实错误/陈旧状态，不能用模型动画冒充数据在线。

## 验收证据

`manifest.json` 记录资源哈希、模块、场景设置及动画信息，`local-projects.json` 记录实际项目入口；`qa/verification.json` 和同目录截图记录本次保存页面的验收；`qa/metric-balances.json` 记录每案例 240 个采样时刻的模拟关系核对及重载后源接口检查，差值均在三位小数输出的舍入范围内。共 29 个模型加载成功，动画目标有变化、坐标有限且 12 秒资源循环一致；26 台业务设备指标可采集；六个页面各使用一个 renderer，设备选择与模拟数据提示正常。截图变化只证明动画播放，不是 FPS 基准。
