# NewPower 独立交付

项目 ZIP 保存某个已冻结版本及资源；程序 ZIP 提供本地运行服务。两者可以从已登录的界面下载，安装程序需要 Node.js 24.18 或之后的 24 系列版本。

## 制作与安装

1. 在项目发布面板完成检查、冻结版本，再下载该版本的项目 ZIP。
2. 在项目列表打开“导入项目包”，下载独立运行程序。解压到一个新目录，运行 `./start.sh`（macOS/Linux）或 `start.cmd`（Windows）。
3. 首次启动生成私有 `runtime.env`，默认地址为 `http://127.0.0.1:8792`。按包内 README，用 `initialize-admin.mjs --email 邮箱 --password-file 私有密码文件` 创建管理员。密码文件只用于初始化，完成后可移除。
4. 登录新服务，上传项目 ZIP。检查页面会列出页面、资产、模型、图片及所需环境端点；确认后安装为新项目，保留安装结果中的目标项目 ID。
5. 按包内 `sources.example.json` 配置私有环境，将真实地址、认证及目标项目白名单放入私有 `sources.json`。在 `runtime.env` 设置 `SOURCE_ENVIRONMENT_FILE`、精确 `RUNTIME_ALLOWED_HOSTS` 并启用采集，重启服务。
6. 在发布面板激活版本并打开运行入口。如需编辑，选择“恢复为可编辑草稿”，检查覆盖预览后确认。安装不会自动替换已有草稿。

## 升级、回滚与内网

后续项目 ZIP 在目标项目的发布面板安装为新版本，检查后再激活。回滚选择先前保留的版本；已经打开的固定版本页面维持原版本，新打开的“当前发布”入口进入当前指针。

运行程序升级前停止旧进程，备份数据目录与私有环境，再替换程序文件。启动检测迁移历史，有新迁移时先备份验证。项目回滚只切换项目版本；数据库降级需对应升级前备份，旧程序不能直接打开更新后的未知迁移历史。

内网通过可信 HTTPS 反向代理提供同源前端和 API，设置 `PUBLIC_ORIGIN` 为实际访问源，代理保留 Cookie、关闭 SSE 缓冲并允许长连接。需要直接监听内网时可传 `--host`，默认仅监听本机。私有环境和 `data` 不得放进 `public`。

安装中断后重新启动宿主，恢复日志会清理本次未提交资源，已提交版本保留。检查单有一小时有效期，过期需重新上传。遇到未知格式、文件损坏、身份冲突或权限变化，界面会明确拒绝，当前发布版本保持不变。

本机已经验证干净目录启动、真实浏览器导入、原服务停止后运行、恢复编辑、升级回滚及 HTTPS 代理。Windows 脚本与 Docker 环境尚未执行验证，客户工业接口和目标硬件另行验收。
