# M2 项目定义与兼容设计

编辑命令检查点已提交 `7e3edcb`，不是 M2 终点。以下结构已实现，实际验证见 acceptance.md。

## 持久化和兼容

项目定义采用明确 schema 版本，包含入口页、页面列表、项目级绑定定义；页面拥有名字、顺序、尺寸、主题与节点。节点 ID 在项目内唯一，分组 ID 只关联同一页的成员。资源和资产继续项目级存储。

`project_canvases` 保留为项目 CAS revision 根，增加 schema_version 与 entry_page_id；新增 `project_pages`，旧画布迁移成稳定 `main` 页；`canvas_nodes` 增加 page_id/group_id，原节点和绑定 ID 不变。根的旧主题字段只作旧数据迁移来源，之后页面表拥有页面内容。

新增完整定义 GET/PATCH，PATCH 只写改变的页面/节点，并在同一版本事务处理入口页和绑定。保存与绑定垃圾回收查看全项目所有页。原 `/canvas` 接口是入口页或指定页的兼容投影，保留现有 M1/3D 消费者；页面局部绑定提交与其他页定义合并后统一校验。封面继续读取入口页，缓存使用项目 revision。

模型编辑路由、加载、保存和返回必须携带所属页；旧 URL 默认入口页。编辑历史拥有整个项目定义，当前页/选择是会话状态，不属于持久化内容；跨页移动保留节点 ID，复制产生新节点/绑定/分组 ID。

## 用户操作

- 页面新增、命名、复制、排序、删除、入口页切换及跨页移动；不能删除最后一页。
- Shift 多选、分组/解组、组内一起移动和复制；变化进入同一操作/撤销链，预览数据不进入历史。
- 草稿按用户和项目隔离，包含项目定义与所基于的服务端 revision。刷新后可恢复；服务器有更新时必须显示冲突与差异，不能悄悄覆盖。同版本草稿仅在保存成功后清除；冲突草稿放入独立队列，继续编辑和保存不得覆盖，明确恢复/放弃才消费，存储失败必须提示。
- 继续复验复制绑定组件、旧模板和单设备模型。多页重点检查另一页内容/绑定不被保存或回收影响，3D 返回 B 页、入口页封面更新、版本冲突和权限。

共享解析与命令层继续承接后续 M3/M4/M5/M8；不建立与编辑器互不相通的运行 schema。
