# M6b 历史、告警与可扩展数据源

首项链路为持续采样→标准化→历史持久化→告警发生/恢复→查询界面。旧实现只在客户端update中标准化资产，现已把历史与告警入口接到服务端源帧边界；无人查看也执行，查看者数量不增加记录。

## 统一边界

按项目及固定版本划分运行scope，草稿另记完整配置修订。采样身份包含宿主epoch、源任务代次及序号，订阅数不影响样本身份。多源资产只将本次更新源的指标写成新样本；保留源时间、采集时间、值类型/单位、质量和错误码。失败/陈旧不可伪装为新实时值。遥测存储与项目配置库分开，写入有界、批量、可诊断，并有明确保留策略；写入失败不能宣称已保存。

告警定义为冻结配置，活动状态和历史事件为运行数据。复用受校验条件的三值语义，规则ID稳定，发生/恢复只在状态转换时记录；失联或陈旧为unknown，不自动恢复正在发生的阈值告警。重启保留活动事件，获得有效新样本前状态待确认。草稿与发布版本查询严格分开，权限按所属项目校验。

## 第一项验收

1. 实际持续REST服务、两台资产，零浏览器订阅仍记录历史。
2. 阈值穿越只发生一次，重复超限不重复；失联/陈旧不假恢复，有效恢复样本生成恢复记录。
3. 停机重启后历史和活动告警可读，旧值不作为当前正常。
4. 增加两个浏览器不使样本翻倍；改变草稿映射不影响固定发布记录。
5. 配置/查询界面、时间范围与分页、权限和持久化失败有实际验证。

随后沿同一边界接入WebSocket历史、图表与告警组件正式绑定、转换配置、MQTT及只读SQL适配。协议连接/取消/重连/消息边界复用M6a，环境凭据继续由服务器拥有，浏览器不直接访问工业服务。完整M6b验收还需本地真实协议服务和异常集成，不以首项链替代阶段完成。

## 历史首项实现

Node通过每源TelemetryPlan获取该scope的全部正式指标映射；草稿加载前后核对完整runtimeRevision，固定版本直接取冻结快照。每个指标独立复用原标准化逻辑，坏字段不连带丢掉其他字段，也不重写另一来源的缓存值。源任务epoch/UUID/序号构成sampleId；有效采样逐次保存，缺值/错误/陈旧质量只记录变化。WS有独立于查看者的陈旧检查，历史计划短暂失败每秒重试，不依赖WS重新连接。

独立telemetry.sqlite使用单独telemetry-migrations和同一个已验证迁移/备份工具，避免触发项目修订。队列最多10000条，每100ms通常处理最多1000条；单源大帧可以整帧写入至10000条，不能拆半求值。超过队列时整帧拒绝，文本值上限4096字节；失败整帧保留有界重试，无法提交退出时记录真实缺口。默认7天/全宿主100万条，两者先到者生效，不宣称工业吞吐。查询只读已提交行，时间范围最多31天、每页最多200条；按授权项目、draft/固定版本、资产/指标及游标分开。UI目前每页100条并明确显示历史质量与配置修订。

停机先停止采集/HTTP处理，再排空遥测并关库。最后写入失败会显式报错，私有.gaps.json保留缺口诊断供下次启动恢复；如果磁盘连缺口文件也不能写，stderr明确记录错误，不伪装正常停机。未正常退出的.running标记使下次启动报告可能有未提交队列缺口。队列接收不等于已持久化，SIGKILL可能丢失尚未提交的短队列，不能据正常重启测试声称零丢失。

删除项目同步取消草稿和全部固定版本源/订阅，过滤待写队列并清理历史。若删除与进程故障交错，启动以配置库仍存在的项目核对遥测行与gap恢复后的内存状态，继续清理；不会只清表后又由旧固定订阅写回。最后查看者定时器也随删除释放。

## 后续告警接入决定

告警定义独立于浏览器交互状态，使用稳定规则ID、所属资产、受校验的条件/恢复条件、级别与消息；配置写入遵循项目完整CAS，随冻结快照和项目包交付。运行快照升级需明确能力声明，旧运行器遇到不支持的告警/转换能力应拒绝，不能静默忽略。

告警状态与发生/恢复事件在遥测事务内维护。先确保涉及的指标均为当前有效值，再复用三值条件求值；缺值、陈旧、失联或重启未确认时维持unknown，不自动恢复活动告警。配置依赖变化应标明规则已替换/停用，不能冒充正常恢复；无关布局修改也不应重复生成同一活动告警。项目级配置和查询面板已接入，后续继续把原静态告警组件接正式数据绑定。该组件绑定、转换和MQTT/只读SQL仍未完成，当前不是M6b总验收。


## 告警实现与异常语义

0019保存项目范围规则ID、规则配置与完整CAS审计，增删改推进runtimeRevision。服务端条件仅允许所属资产指标与常量，复用可视化条件编辑器与三值求值。发生/恢复在同一遥测事务中记录，提交后才更新内存指标缓存；同一源帧所有指标一起可见，数据库回滚不留下内存“成功值”。

快照v2带alarmRules与requiredCapabilities，告警必须声明alarm-rules-v1；未知能力拒绝。旧v1保留原表示、哈希及包身份，不补新字段；新v2检查单保留wireManifest，以合法原始manifest计算来源身份，规范化运行视图不能重算成另一个来源包。恢复v1明确清空草稿规则，已有冻结版本不可变；导入/恢复预览显示告警数量。Node提供告警执行，Worker可编辑/保存但不能激活要求告警执行的版本。

规则依赖签名包含条件、所属资产、指标映射和实际逻辑来源；无关布局、规则名称/消息/级别和采样频率修改不会重新产生同一活动episode。发生时的名称、级别和消息留在该episode，后续新发生采用新配置。条件、映射等语义变化会留下configuration_changed/retired，不能伪装正常恢复。最后按需订阅退出后状态待确认，再订阅仍延续原活动episode；持续模式无人查看继续判断。

写库异常不能挡住采集代次失效：先取消旧源任务，再尝试告警持久化。草稿/固定版本的配置恢复独立重试。失败或整帧拒绝使告警状态立即不确定；每条入队记录附scope代次水位，水位之前的旧排队/重试数据只补历史，不得把新的未知状态冲掉。只有水位之后的采样能重新确认状态。失败批次成功重试且没有丢弃记录后，写入延迟诊断恢复；实际丢弃与关闭缺口仍保留。

事件保留30天、全宿主最多20万条；已结束且没有保留事件的episode回收，未结束的活动episode单独保留。API按项目及固定版本授权并支持时间/状态/游标查询，面板每页50条，第一页每3秒更新，分页固定查询时间窗。界面“当前数据有效”指服务器取得有效数据，不表示人工确认告警。
