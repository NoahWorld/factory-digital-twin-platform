# M6b 历史、告警与可扩展数据源

第一项完成持续采样→标准化→历史持久化→告警发生/恢复→查询界面。当前源采样独立于查看者，但资产标准化仅在客户端update中执行，因此历史入口必须移到服务端源样本处理边界；不能挂在浏览器/SSE回调，否则无人查看漏记、多查看者重复。

## 统一边界

按项目及固定版本划分运行scope，草稿另记完整配置修订。采样身份包含宿主epoch、源任务代次及序号，订阅数不影响样本身份。多源资产只将本次更新源的指标写成新样本；保留源时间、采集时间、值类型/单位、质量和错误码。失败/陈旧不可伪装为新实时值。遥测存储与项目配置库分开，写入有界、批量、可诊断，并有明确保留策略；写入失败不能宣称已保存。

告警定义为冻结配置，活动状态和历史事件为运行数据。复用受校验条件的三值语义，规则ID稳定，发生/恢复只在状态转换时记录；失联或陈旧为unknown，不自动恢复正在发生的阈值告警。重启保留活动事件，获得有效新样本前状态待确认。草稿与发布版本查询严格分开，权限按所属项目校验。

## 第一项验收

1. 实际持续REST服务、两台资产，零浏览器订阅仍记录历史。
2. 阈值穿越只发生一次，重复超限不重复；失联/陈旧不假恢复，有效恢复样本生成恢复记录。
3. 停机重启后历史和活动告警可读，旧值不作为当前正常。
4. 增加两个浏览器不使样本翻倍；改变草稿映射不影响固定发布记录。
5. 配置/查询界面、时间范围与分页、权限和持久化失败有实际验证。

随后沿同一边界接入WebSocket历史、图表与告警组件正式绑定、转换配置、MQTT及只读SQL适配。协议连接/取消/重连/消息边界复用M6a，环境凭据继续由服务器拥有，浏览器不直接访问工业服务。完整M6b验收还需本地真实协议服务和异常集成，不以首项链替代阶段完成。
