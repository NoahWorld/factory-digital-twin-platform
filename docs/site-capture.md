# 写实漫游：采集、生成与部署

**当前状态（2026-10-14）：因服务器不具备 GPU 重建条件，按用户决定暂时隐藏写实漫游。** 功能中心不展示入口和相关介绍，资源库不挂载任务面板、不请求写实任务接口；保留前后端实现与已有数据。统一发布开关位于 `apps/web/src/pages/scene-background.ts` 的 `SITE_CAPTURE_RELEASED`，待 GPU 部署及真实重建验收具备条件后再确认恢复开放。

以下说明保留实现的技术和验收约定，不代表当前已经对用户开放。恢复后的入口为：资源库 → AI 场景底座 → 写实漫游。首次进入先显示采集要求；任务管理、上传与查看器属于独立工作区，可返回功能中心。

## 已实现及验收边界

实现链路为：保存原始素材 → 检查清晰度与画面 → COLMAP 恢复相机与稀疏空间 → gsplat CUDA 优化高斯场景 → 输出 Gaussian PLY → 浏览器自由漫游。

**当前没有可用的 NVIDIA GPU 服务器。** Java API、真实数据库/对象存储、任务恢复与浏览器查看器可以独立验证；CUDA 构建、真实采集重建、显存需求、耗时与最终画面仍需要在实际 GPU 上验收。合成 PLY 的 WebGL 测试只证明查看器能工作，不能充当实拍重建成功的证据。

保留的任务接口在未接入健康 GPU 工作节点时支持上传和保存素材，但不能开始生成；当前界面隐藏期间不提供上述操作入口。重建能力由工作节点真实探测和新鲜心跳决定，发布开关不能假装 GPU 可用。

## 输入限制与拍摄要求

| 方式 | 文件与数量 | 容量及画面边界 |
| --- | --- | --- |
| 照片 | 一次 8–120 张 JPEG/JPG、PNG 或 WebP | 单张 8 MiB，合计 500 MiB；长边至少 480、短边至少 360 像素，最多 4000 万像素 |
| 视频 | 一次 1 个 MP4 或 WebM 连续片段 | 100 MiB；4–600 秒，1–60 fps；短边至少 360、长边不超过 4096 像素，总像素不超过 3840 × 2160（支持横竖画面） |
| 结果 | 当前工作节点输出 SH0 Gaussian PLY | 最多 200 MiB、100 万个高斯点 |

不能混合照片与视频，不接受空文件、同名文件（忽略大小写）、路径形式的文件名。文件名最多 240 个字符。UI 的 MB 按 1024 × 1024 字节计算，即本文 MiB。浏览器先检查数量和容量，服务器检查签名，工作节点解码后检查分辨率和画面。8 张照片只是最小输入数量，无法保证覆盖一个房间。

- **范围**：同一个静态单房间或连通的局部车间。大型厂区、互不连通的房间应分别采集。
- **视角**：缓慢移动相机位置，相邻画面充分重叠。关键区域建议至少覆盖 3 个不同位置，兼顾通道、墙角、设备周边及不同高度；只在原地转动相机不适合空间重建。
- **稳定性**：同一拍摄时段，光照和现场布置稳定。保持画面清晰、曝光适中，不要边拍边变焦或切换镜头。
- **原始素材**：照片保留原图，视频保留同一空间的连续片段，不剪辑拼接，不加字幕、滤镜或转场。
- **困难区域**：玻璃、镜面金属、大面积纯白或重复纹理、运动人员与设备，可能造成定位失败、缺失或重影。未拍到的区域无法可靠还原。
- **比例**：可记录一段两端清晰的已知长度，供未来标定。当前结果为重建空间的任意比例，不提供米制标定、工程测量、构件编辑或实体碰撞。

首版使用 SH0 表达外观，不表达随视角变化的高光。对反光材料应降低预期。工作节点会检查相机注册率、稀疏点数、重投影误差和训练视图图像误差；这些指标用于拒绝明显失败，不能保证未见视角质量。生成后仍应实看关键区域、遮挡处和通道。

## 使用与状态

1. 阅读要求，填写名称，选择素材并确认。上传时显示文件、数量和用时；界面保持响应。
2. 关闭面板不终止上传，但关闭网页或切换项目会中断当前文件。返回任务、重新选择原始素材后，仅补传尚未保存的槽位。上传不是字节级断点续传，每个未完成文件会重新上传。
3. 服务就绪后点击“开始生成漫游”。服务器显示实际阶段和计数：读取素材、检查画面、视频抽帧、特征匹配、相机求解、场景优化、导出。没有伪造的总百分比。
4. 生成任务保存在数据库中，关闭页面不终止后台生成；租约到期可由工作节点重新接管，过期执行不能覆盖新结果。
5. 成功后进入查看器，用拖动、WASD/方向键、Q/E 或触摸按钮浏览，可调速度和复位。查看器显示加载状态，并支持失败重试与返回任务。请求或下载连续 30 秒没有新数据时会终止加载、释放资源并提示重试；正常持续下载不受 30 秒总时长限制。
6. 失败会显示阶段、可理解的原因与任务编号；日志保留诊断。失败可重试，活动任务可取消，删除任务须确认且会删除关联源文件和产物。

网络失败保留最后一次确认的任务状态，显示重连次数；后端未升级显示服务提示，不显示“内容不存在”。

## 接口与权限

Java 后端 `TWIN_MODE=api` 提供：

- `GET /api/v1/site-captures/capabilities`：工作节点可用状态及限制。
- `GET/POST /api/v1/projects/{projectId}/site-captures`：列表、创建幂等草稿。
- `GET/DELETE .../{captureId}`：任务详情、删除。
- `PUT .../{captureId}/sources/{index}`：按声明槽位上传；相同字节重试幂等，不同字节拒绝覆盖。
- `POST .../{captureId}/start|cancel|retry`：显式开始、取消、重试失败任务。
- `GET .../{captureId}/content`：鉴权后同源流式返回 PLY，不向浏览器暴露对象存储凭据或外部下载跳转。

遵循租户、项目与资源库模块权限。只读用户不能创建或修改任务。原始素材和结果存入现有 S3 存储，任务与心跳由 V9 PostgreSQL 迁移管理。不要通过通用媒体导入接口代替该任务链。

## 本地与离线部署

CPU API 使用正常后端镜像，无需安装 Python、CUDA 或模型权重。写实重建独立使用 `TWIN_MODE=capture-worker`，不占用 IFC/DXF 的工作线程。

GPU 镜像源码、固定版本依赖、检查和导入导出脚本位于相邻后端仓库 `capture/`；详细构建说明以该目录 README 为准。当前交付包含代码与构建/导出脚本，尚未构建和验收 GPU 镜像 tar，不能直接当作已验证的离线安装包。基本流程：

1. 在有外网的 Linux 构建机按目标架构构建 GPU 镜像；构建期安装并预编译所有依赖。
2. 导出镜像及校验值，搬到内网后校验并导入。运行期不下载 Python 包、模型或 CUDA 扩展。
3. GPU 主机须预装兼容 NVIDIA 驱动与 NVIDIA Container Toolkit，并可访问平台 PostgreSQL 和 S3。镜像不能代替宿主机 GPU 驱动。
4. 运行 `--probe` 验证 CUDA、gsplat 已编译扩展、COLMAP 与 ffmpeg，再接入任务服务。应使用独立数据卷作临时工作目录，不将大规模重建写入 API 的小容量 `/tmp`。
5. 有实际 GPU 后执行真实素材验收：至少一个满足要求的空间、一个覆盖不足样本、重建中取消/重启、断网运行，以及产物的实际漫游观感。记录型号、显存、素材、耗时、峰值资源与结果。

可选 Compose 位于 `deploy/local/capture.compose.yml` 和 `deploy/server/capture.compose.yml`，只适合 GPU 与各依赖位于同一 Docker 主机的对应部署。跨主机工作节点必须提供实际可达的私网数据库和 S3 地址及凭据；不要直接复制 loopback 地址。没有 GPU 时不启用该 profile。16 GiB 容器内存限额是可调运行预算，不是已验证的硬件最低配置。

本地同机启用命令（须先准备 GPU 镜像和宿主机驱动）：

```sh
docker compose --env-file deploy/local/.env -f deploy/local/compose.yml -f deploy/local/capture.compose.yml --profile capture up -d --no-deps capture-worker
```

服务器同机部署在既有 compose 命令中追加 `-f deploy/server/capture.compose.yml --profile capture`，使用原服务器受控环境文件。不要把本地 `.env` 覆盖到服务器。

启用 GPU 工作节点后，备份和恢复必须同时暂停 `capture-worker` 与原有 API/worker 等写入者，再备份数据库与对象存储；跨主机工作节点也须暂停。`pnpm backend:backup` 已纳入本地可选工作节点，仅恢复备份前已在运行的服务。`capture-work` 是可重新生成的临时空间，不代替数据库和原始素材备份。

前端：`pnpm check`、`pnpm build`、`pnpm test:scene-background`、`pnpm test:scene-background:browser`、`pnpm test:site-capture:browser`、`pnpm test:site-capture:viewer`。浏览器脚本使用 Playwright；可通过 `PLAYWRIGHT_MODULE_PATH` 指定已安装模块。

真实本地浏览器：`pnpm test:site-capture:live`。需要 Vite `127.0.0.1:5173` 代理到已迁移 V9 的本地 Java API（本次为 `127.0.0.1:18080`），数据库与 S3 可用、`deploy/local/.local/admin.json` 已配置，以及 FFmpeg（含 libx264/libvpx-vp9）、cwebp、Playwright 和 Chrome。脚本明确要求 GPU 当前不可用，只创建和删除自己带唯一标识的项目、任务和会话；不会重置用户或修改既有项目。证据与截图存入被 Git 忽略的 `deploy/local/.local/site-capture-tests/<runId>/`。它验证真实传输与持久化，合成图片/视频不是重建素材，不能据此判断画质。

接口、输入和输出约束修改时，同步更新前端 `site-capture.ts` / `scene-background.ts`、Java `SiteCaptures` / `SiteCaptureResult`、Python `capture/core.py`、导入前提示及本文。

### 本轮修复

- 查看器连接或下载中途停滞会无限等待。修复为连续 30 秒无数据时显式失败、终止请求并允许重试；测试已先复现失败，再验证修复、取消释放和长时间正常下载。
- Python 首次磁盘预算检查依赖单调时钟的起点，部分运行环境可能延迟首次检查。初始化改为必须立即执行第一次检查，保留后续节流。

### 已确认但未解决的缺口

历史任务超过 100 条后，较早任务无法从页面列表进入。后端 `src/main/java/com/factorytwin/SiteCaptures.java` 的列表 SQL 固定 `ORDER BY created_at DESC LIMIT 100`，前端没有分页。独立空 PostgreSQL 中插入 101 条终态任务后，真实列表返回 100 条，最旧任务不在列表；按 ID 读取该任务仍成功，8 个素材槽位完整。数据没有丢失，但历史入口不完整；复现成功不算该行为验收通过。本轮未扩展分页接口。
