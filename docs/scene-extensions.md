# 房间报警、环境与军事模型、静态地图

植物、水景和军事模型统一从独立 3D 编辑器左侧“模型库”添加，右侧“场景扩展”编辑参数、报警和地图，通过原有“保存场景”保存。2D 的 `scene-3d` 引用和固定版本运行页复用同一渲染层。普通 2D 组件、原模型文件、流体配置和已有内置模型 ID 不改写。

## 操作

| 入口 | 可配置内容 | 保存方式 |
|---|---|---|
| 左侧模型库 → 植物 / 水景 | 乔木、灌木、河流；右侧编辑颜色、位置、旋转、缩放、植物种子、河面路径、宽度、流速、透明度与播放 | 参数化对象，可添加、复制、删除和修改 |
| 左侧模型库 → 军事模型 | 通用运输车、帐篷、雷达、装甲车的静态外形；右侧编辑颜色和变换 | 仅保存参数，共享实现，不新增模型或纹理文件 |
| 房间报警 | 数据项目、业务资产、指标键、比较条件、颜色、模型实例与房间节点 | 只读观察，不发送设备控制命令 |
| 地图 | 本地 GeoJSON 文件或粘贴 JSON；区域颜色、高度、地图宽度、变换、显隐 | 浏览器校验及预览后保存规范化地图配置 |

房间须在模型中具有名称唯一、可以单独选择的子节点；整栋建筑只有一个网格时不能自动推断房间。报警支持布尔/文本等于以及有限数值比较，数据来自当前 3D 项目或已关联、已授权的 2D 项目的标准化 REST 指标。先在资产与数据配置中建立数据源、资产和指标绑定，再选择房间。

每个指标携带自己的 `sourceId`、`timestamp`、`collectedAt` 与质量；多源资产不使用整资产最早时间代替火警指标的采样时间。断线、缺值、陈旧、身份矛盾和重复时间戳的冲突值均不能解除已触发的报警；界面显示相应状态，新的有效恢复值才能清除报警。规则停用或移除恢复当前静态外观，材质修改仅属于目标实例的房间子树。

未应用的 JSON、空数值和错误参数不会被当成保存成功。导入地图失败保留现有地图；模板和灯光调整继续保留场景扩展配置。图层、视窗拾取与属性选择同步。

模型库按工业模型、植物、水景、军事模型、上传模型和背景模型分类；程序化对象显示类别图标，原有模型沿用真实静态缩略图。已有场景中的植物、水景和军事对象无需转换或重建：选中后点击“移动 W”或“缩放 R”，拖动视窗中的坐标轴；缩放中心手柄可等比调整。拖动时相机暂停旋转，松开后同步右侧数值与待保存状态，再点击“保存场景”。也可继续在右侧精确输入位置、旋转和缩放。预览及只读状态没有操作轴。未完成参数输入时先修正或放弃输入，再进行视窗变换。

这些对象仍保存在既有 `decorations` 字段中，ID 与场景修订链保持不变。只修改位置、旋转、缩放、名称或显隐时复用现有几何；改变种类或几何参数才重新生成对应对象。地图继续通过右侧属性调整变换。

## 静态地图格式与边界

支持 `FeatureCollection` 中的 `Polygon`、`MultiPolygon` 和洞。坐标严格二维；选择本地 X/Z 平面或 WGS84。WGS84 使用中心附近的平面近似，再按配置宽度归一，不用于精密地理测量。只消费稳定字符串 ID、`properties.name`、`properties.height`、`properties.color`；缺少 ID 时按导入顺序生成。不会加载外部 URL、瓦片或脚本。

```json
{"type":"FeatureCollection","features":[{"type":"Feature","id":"zone-a","properties":{"name":"区域 A","height":3,"color":"#46798d"},"geometry":{"type":"Polygon","coordinates":[[[0,0],[10,0],[10,8],[0,8],[0,0]]]}}]}
```

| 对象 | 上限与校验 |
|---|---|
| 装饰 | 64 项；位置 ±10000，旋转 ±3600°，缩放 0.001–100 |
| 河面 | 2–64 点；宽度 0.1–100；拒绝退化段、折返及河岸自交 |
| 报警 | 64 条；最多 50 个不同数据资产；最多影响 256 个网格；重名、重叠或失效目标明确报错 |
| 地图 | 512 KiB，64 个区域，4096 总点；每区域最多 16 个多边形，每多边形最多 8 个洞，每环 4–257 点；闭环、退化、自交、洞越界和日期线跨度均检查 |
| 场景合计 | 模型、装饰和地图共同受 128 实例、6000 估算网格、24 动画实例限制；参数化对象不能绕过预算 |

军用对象仅提供通用静态展示外形，不附加动作或作战逻辑。新增程序几何没有贴图/GLB 二进制；实际项目存储大小由参数 JSON 决定，运行时几何成本另行统计。

## 契约、后端与兼容

`shared/scene-decorations.ts`、`shared/room-alarms.ts`、`shared/static-map.ts` 是配置来源。场景同级增加 `decorations`、`roomAlarms`、`staticMap`，Java 在既有 settings JSONB 内保存并在 API 拆出，沿用场景修订事务及封面失效。省略保留；两个数组用 `[]` 清空，地图用 `null` 删除；仅旧数据缺失时默认，损坏存储不伪装为空。

实例删除、模型替换、取消关联、业务编号/指标类型修改或删除绑定须检查最终报警引用。数据和选择状态不写回配置。新能力由 Java 场景响应的 `sceneExtensionsVersion: 1` 标明；历史 Worker 对新字段明确返回 501。

固定发布版本冻结这些配置及既有资产/资源定义。白名单内置图片和模型保留不可变 ID 与静态文件，不伪装成上传资源。原有单数 `publication` 公开分享按既定规则读取当前已保存内容，与复数 `publications` 固定版本不同。

后端开发和构建目标是独立的 `NoahWorld/factory-digital-twin-backend/main`。平台 `apps/backend` 保留为历史参考。默认将两个仓库放在同一父目录；其他布局设置绝对路径 `TWIN_BACKEND_DIR`，或给契约命令传 `--backend-dir`。Docker Compose 同样使用该目录，不部署旧快照。

```sh
pnpm backend:contracts
pnpm backend:contracts:check
pnpm backend:verify
pnpm test:scene-extensions
pnpm check
pnpm build
```

## 验证入口

定向测试检查几何、材质隔离、释放、指标时间身份、类型和预算。真实 API 测试要求显式的隔离 `SCENE_TEST_DIR`，仅访问本机 18081；浏览器测试使用 5176、独立浏览器会话和同一份模拟数据 fixture，不写业务项目。`PLAYWRIGHT_MODULE_PATH`、`CHROMIUM_EXECUTABLE` 复用已安装工具，不运行时下载。

```sh
node scripts/test-scene-extensions-api.mjs --keep-fixture
node scripts/test-scene-extensions-browser.mjs
```

这些命令须先准备该目录中受限权限的测试环境与账号文件；不会自动使用业务账号。测试创建的固定发布版本受删除保护，清理必须通过正式 API 并如实保留被保护对象，不能绕过约束删除数据库记录。示例中的房间、指标和场区均为模拟数据。

模型库和操作轴的独立浏览器回归使用临时本机页面、内存 API 和真实 Three.js 渲染，不需要业务账号，也不访问生产数据：

```sh
pnpm test:model-library:browser
```

可用 `PLAYWRIGHT_MODULE_PATH` 指定已安装的 Playwright 模块。回归覆盖七种参数化模型创建、分类、真实鼠标移动与缩放、拖动中断恢复、保存重载、参数校验与删除、原有 GLB 以及只读/预览状态。

## 场景扩展初版的本机验证记录

前端与 Worker 类型检查、构建、跨仓库契约一致性，以及独立 Java 后端的 94 项测试全部通过。装饰、房间报警、指标时间身份及静态地图的定向测试通过；原场景、独立 3D 和流体相关回归通过。

隔离 PostgreSQL、Valkey、对象存储与真实 Java API 验证了保存/重开、错误输入的事务回滚、修订冲突、权限、引用保护、128/129 实例和 24/25 动画预算边界、固定发布冻结。模拟 REST 源覆盖火警触发、断线保留报警、新值恢复以及同一资产内慢源与快源的独立指标时间。

浏览器 8 条验收路径通过：创建植物、军事对象变换、报警变量与房间配置、地图导入及错误保留、深色与紧凑布局、目标房间变色与断线恢复、无关联地图固定发布、关联内置图片发布。两个实例共享同一模型时，仅指定实例的指定房间变色，其他房间保持原样。

以上是场景扩展初版的本机模拟数据验收；浏览器使用软件渲染，不作为客户硬件帧率或生产规模性能结论。该次初版验收不包含外部部署；当前部署与模型库升级验收记录见 `deploy/server/README.md`。
