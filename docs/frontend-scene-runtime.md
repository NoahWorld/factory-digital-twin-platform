# 前端场景运行架构

日期：2026-09-09。关联评估：[厂房场景架构评估与技术选型](./厂房场景架构评估与技术选型.md)。本轮以编辑器和运行层调整为主；为使实例外观与动画设置可持久化，仅通过 `0019_standalone_3d_instance_presentation.sql` 扩展既有独立场景实例表，采集服务及其他后端架构保持原状。

## 技术决定与实际实现

保留 React 19、TypeScript、Vite 和 Three.js WebGLRenderer。新增 `three-mesh-bvh` 和 `@dimforge/rapier3d-compat`（锁定版本 0.20.0），暂不引入 R3F、WebGPU 或状态框架。Rapier 只负责静态碰撞场景中的角色移动，Three.js 继续负责渲染和拾取。

| 模块 | 职责与边界 |
| --- | --- |
| `canvas/BatchModel3DNode.tsx` | React 挂载、配置、指针事件、控制面板和低频加载状态；动态加载运行层 |
| `scene/scene-runtime.ts` | 单 renderer、相机、光照、动画、配置增量应用、选择高亮、实例操作轴、诊断与销毁 |
| `scene/instance-transform.ts` | 将 Three.js 实例变换转换为度制保存契约，并约束鼠标缩放范围与数值精度 |
| `scene/resource-manager.ts` | 场景内按资源 ID 合并加载；最多 3 个加载任务；每实例持有租约；最后一个引用释放源资源 |
| `scene/model-loader.ts` | 同源模型请求、上下文错误、元数据验证、本地 Meshopt/KTX2/Draco 解码和静态几何 BVH |
| `scene/instance-manager.ts` | 以实例 ID + 模型资源 ID 复用对象；新实例准备后替换；管理混合器、克隆骨骼与材质 |
| `scene/picking-service.ts` | 实例包围盒筛选、静态 BVH、可见对象拾取，返回实例 ID 与主模型会话路径 |
| `scene/walk-physics.ts` | 延迟初始化 Rapier WASM、校验米制碰撞配置、胶囊角色、固定步长、边界错误与物理世界释放 |
| `scene/walk-controls.ts` | 聚焦画布后的键盘移动、拖动看向、失焦释放、独占相机；不持有 React 状态 |
| `decoder-assets.ts` | 从锁定的 Three.js 包输出同源解码脚本与 WASM；开发和生产统一路径 |

单模型兼容组件仍保留原有检视/后处理逻辑，仅接入同一套本地解码器；本次运行层拆分主要覆盖多实例及独立场景入口，不能宣称全部旧代码已经统一。

独立 3D 编辑器把当前草稿的实例数组作为左侧图层树的唯一数据源，画布拾取与图层点击共同更新同一个选中实例 ID。右侧模型属性分为基础信息、变换、外观和动画，场景属性分为项目关联、背景、灯光、相机和全局动态；这些面板都直接编辑同一份待保存草稿，不维护浏览器私有副本。实例颜色、透明度、动画启停和动画速度经独立场景补丁接口保存，旧实例缺少字段时按无颜色覆盖、完全不透明、动画开启和 1 倍速度读取。

## 生命周期约定

- renderer 只在容器挂载、项目或组件身份变化时创建。增加、删除、重排或替换实例，不重建 renderer，不重新解析仍被引用的资源。
- 实例变换、选择、相机控制开关不应触发模型下载。仅选择变化不重置材质、动画姿态或实例变换。
- 图层树与画布选择必须双向同步；选择态只使用 Three.js `BoxHelper` 和操作轴表达，不进入持久化数据。实例颜色或透明度变化时只克隆并替换该实例使用的材质；清除覆盖、替换资源或销毁实例时恢复共享源材质并释放克隆。
- 场景总动画开关控制全部混合器；实例动画开关和速度在此基础上分别决定该实例是否推进及推进倍率。关闭实例动画时保留当前姿态，重新开启后继续推进；动画预算只统计当前实际启用动画的实例。
- 独立场景编辑页使用 `TransformControls` 直接操作已选实例的 wrapper。拖动过程留在 Three.js 运行层以保持画面响应；鼠标松开时才向 React 回传一次规范化变换并标记草稿待保存。切换选择、删除或替换资源时必须先解除挂载，不能让操作轴保留已销毁对象引用。
- 同一资源的多个请求者各有取消信号；取消其中一个不会破坏其他引用。排队任务取消后不得启动实际加载；在途请求尽可能通过 AbortSignal 取消。
- glTF 解析不支持完整的同步中断；已开始解析的结果完成后检查取消并释放。解码工作完成后才销毁 worker，避免终止 worker 留下悬空解析任务。
- 新资源失败时保留上一次场景用于定位，但立即显示错误；该场景不能标记为更新成功。取消/被新配置替代属于显式生命周期行为，与加载失败区分。
- 源资源拥有几何、纹理和原始材质；实例拥有克隆骨骼、动画混合器及外观覆盖材质。不能提前 dispose 仍被其他实例引用的源资源。
- 页面隐藏或场景离开视口时停止渲染循环；恢复时重置时间基准，避免动画补跑隐藏期间的时间。
- WebGL 上下文丢失时停止循环并显示错误；后续普通配置更新不能将它改回“就绪”。

## 相机与拾取

首次得到有效边界时取景；显式更换预设视角时重新取景。普通增删模型、改灯光、改外观和窗口调整不强制复位相机。首次居中建立旋转中心，之后保持场景坐标关系。默认采用 OrbitControls；实例操作轴开始拖动后暂停 OrbitControls，结束后按页面权限恢复，防止移动模型时相机同时旋转。移动操作轴采用世界坐标，缩放操作轴采用实例本地坐标；缩放限制为保存接口同样接受的 0.001–1000。显式提供 `WalkSceneConfig` 的组件可进入 Rapier 行走，接入方式与限制见 [Rapier 前端行走](./frontend-rapier-navigation.md)。未提供碰撞配置的现有项目继续只显示查看模式。

BVH 使用 `indirect: true`，不重排共享几何索引。骨骼和 morph 几何不使用静态 BVH；文件自带的 InstancedMesh 保留原生逐实例拾取；有动画的实例不使用静态包围盒提前排除。拾取保留建筑、墙体的遮挡关系；不可通过删除背景候选对象实现“穿墙点击”。BVH 当前同步构建，复杂模型的主线程暂停仍需实测和后续 Worker 优化。

持久化绑定继续使用业务 `assetId`；资源加载代码中的历史字段 `assetId` 实际指模型资源 ID，两者属于不同命名空间。未来接口整理应明确区分 `modelResourceId` 与 `businessAssetId`，不能混用。主模型节点索引路径仍只供当前选择会话使用。

## 诊断与验证

资源加载日志包含 projectId、模型资源 ID、文件字节、耗时和失败原因。运行层每两秒采样实例数、资源数、活动/排队加载数、平均帧间隔、draw calls、三角面、几何/纹理数量与相机位置。Rapier 行走时增加模式、脚底坐标、是否贴地、最近步进碰撞体 ID、步数和累计丢弃的补跑时间；导航初始化/运行失败另行上报并退出行走。可通过容器 `data-scene-diagnostics` 或运行层 `diagnostics()` 读取；不将 Three.js 对象或每帧状态放进 React。

这里的纹理数量不是显存字节，平均帧间隔不是 GPU 时间，也不是 P95/P99。验收需单独记录目标设备、浏览器、分辨率、资源清单、帧耗时分位数、点击延迟及长时间内存趋势。

验证命令：

```sh
pnpm test:scene-runtime
pnpm test:standalone-3d
pnpm --filter @factory-twin/web check
pnpm --filter @factory-twin/web build
pnpm test:models
```

可选真实浏览器回归：`node scripts/test-scene-runtime-browser.mjs`。要求开发机/CI 已安装 Playwright 和 Chromium；可用 `PLAYWRIGHT_MODULE_PATH`、`CHROMIUM_EXECUTABLE` 指定工具位置，用 `SCENE_TEST_PORT` 指定本机端口（默认 5199）。脚本不自动安装浏览器；使用临时 Vite 缓存和模拟模型响应，不连接后端、不写项目数据。测试范围是真实 WebGL、模型复用、相机保持、点击、失败恢复、解码器 WASM 格式、Rapier 延迟加载/墙体碰撞/WASD/失焦/Esc/取消与卸载；WASM 校验不等于所有压缩客户模型已经通过验收。

解码器随应用构建分发，无运行时 CDN 依赖。`decoders/LICENSE.txt` 为 Apache 2.0 条款，来源及上游说明保留在各解码器 README。当前 Three.js 的内建资源 URL 也会被 Vite 处理，因此构建目录可能含额外解码资产；按需请求不等于所有产物都会在首屏下载。

## 后续前端阶段与所需契约

1. **统一资产状态与原地 2D 面板**：浏览器 REST 竖切已经提取共享资产轮询 Hook、连接状态条和设备详情；独立 3D 预览可常驻关联项目的 2D 设备看板，模型点击与设备列表反向选择共用 `assetId`，并消费同一运行快照。当前仍需后端集中采集、跨项目资产授权细化和 SSE/WebSocket 推送，界面不会把本地轮询描述为生产实时服务。
2. **实例内部设备绑定**：定义 `instanceId + stableNodeId → businessAssetId`，解决整厂 GLB 和重复设备模型。保存契约需前后端共同确认，不能用浏览器 localStorage 代替。
3. **区域与 LOD**：区域清单包括稳定 regionId、边界、入口、实例归属、资源版本、距离级别与加载优先级；先定义版本化接口，再做区域装载/卸载、滞回和预取。
4. **静态实例化**：对同几何/材质且无需独立骨骼的重复设备使用 InstancedMesh；材质兼容的异构静态对象再评估 BatchedMesh。必须维护 instanceId 与业务资产映射，并测量 draw calls 收益。
5. **室内行走的项目接入**：Rapier 角色控制器和前端 `walkScene` 契约已实现；继续补充真实厂房的碰撞体制作、可视化校验、配置编辑与版本化保存。后续再评估静态简化三角网格、区域碰撞装卸、移动平台和触屏控制。当前只接收独立简化长方体，不自动从展示模型生成碰撞体。
6. **大模型主线程与首屏**：用真实厂房模型测量 BVH 构建、解码和节点实例化；依据证据拆 Worker、安排渐进加载和调整包拆分。当前没有固定帧率或最大设备数承诺。

后端模型优化任务、集中采集、SSE、PostgreSQL/对象存储迁移和发布版本组合均为待办，本次不实施。

## 本轮验证结果

2026-09-09 已通过资源/实例自动化测试、内置模型兼容测试、前端 TypeScript 检查与生产构建，以及隔离的 Chromium WebGL 回归。生产构建仍提示主包和 Three.js chunk 超过 500 kB，未通过提高警告阈值隐藏。真实厂房规模、压缩客户模型端到端、多小时运行和目标硬件帧率尚未验收。

Rapier 增补验证：通过真实 WASM 的贴地、墙体阻挡/滑动、帧率一致性、斜向限速、补跑上限、非法出生点/边界及独立世界释放测试；Chromium 验证延迟加载、相机互斥、按键与取消。兼容包将 WASM 内嵌在单独的延迟 JS chunk，本机构建约 2.86 MB（gzip 约 1.08 MB），首次进入行走才请求；构建仍保留体积警告。

实例编辑增补验证：在实际 98 实例车间的 Chrome 编辑页选中模型，分别拖动 X、Y、Z 操作轴，右侧位置值同步变化且场景进入待保存状态；切换缩放后拖动 X 轴端点，缩放值同步变化，W/R 快捷键可切换工具。拖动后离开页面而不保存，再次打开仍读取原始已保存数据；预览页不渲染变换工具栏和实例操作轴。

图层与分类属性增补验证：在同一 98 实例车间中确认图层数量、顺序和画布草稿一致；点击地坪与 AGV 图层后，画布包围框、XYZ 操作轴和右侧模型标题同步切换。模型库与图层可独立切换，模型属性完整显示基础信息、变换、外观和动画，场景属性完整显示项目关联、背景、灯光、相机和动态。关闭 AGV 实例动画后动画预算由 6 降为 5，重新开启恢复为 6；自定义颜色即时进入实例运行时，地面网格开关即时作用于场景。测试过程中未保存项目，刷新后恢复服务端版本，浏览器控制台没有 error 级日志。

2D/3D 联动增补：2D 画布预览与独立 3D 预览复用 `useAssetRuntimeConnections`、连接状态条和设备详情组件。独立 3D 预览加载关联 2D 项目的资产台账，只轮询场景实际绑定的资产；右侧看板展示在线/异常汇总、设备列表和选中设备指标。模型点击更新看板，设备列表点击反向选中并高亮模型；打开完整 2D 看板时通过 URL `asset` 参数恢复同一设备详情。模拟资产由元数据标记，所有详情明确显示“模拟数据”。
