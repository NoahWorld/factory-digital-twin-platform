# 可配置点位驱动（2026-09-21）

## 数据路径与控制权

`配置的模拟点位 → Java 模拟器实际反馈 → WebSocket 快照 → 节点变换 → 浏览器碰撞事件`。

这是显式标识的模拟数据链路，不是已连接 PLC 的生产采集。目标值只代表命令；模拟器按每个点位配置的最大速度更新反馈。前端只用反馈值计算姿态，没有按帧补走目标、自动推进动画时间或循环播放。工序按全部目标反馈进入容差后转到下一步，超时明确报错，不用固定延时假装到位。

独立配置入口在 3D **编辑页**的“数据与模型”中。点位具有业务资产 ID、指标键、显式 topic、工程单位、量程、初值、速度和陈旧时间。绑定显式指定模型实例 ID、模型资源 ID、唯一节点名、运动类型、单位轴、轴心、换算比例和上级关节。修改配置需要保存；草稿不驱动现场。“接入测试”仅订阅已保存版本，用于核验数据，不发运动命令。预览页没有配置表、点值列表或启动/复位/运行按钮，只保留模拟来源标识及真实异常状态。

启用前关闭被绑定实例的原生动画。保存端与浏览器均检查冲突；未绑定实例的动画独立处理。保存 `simulation: {enabled:true, procedureId, repeat}` 后，由 Java 后台执行器独立初始化并持续推进指定工序，不依赖 WebSocket 客户端。预览只订阅当前反馈，不重置、不启动模拟器；关闭所有浏览器也不停止数据源。循环等待最后一步反馈到位后重新发第一步目标，不瞬移、不重复复位。开启自动源必须启用驱动并配置点位、绑定、工序及全部 topic；自动模式拒绝手动控制命令。旧配置省略 simulation 时保留手动模式，不隐式启用。

前端断线、质量异常和过期反馈冻结模型并报错，重连后使用当前反馈。后台执行器停顿超过 1 秒会保留最后反馈并进入明确错误状态，不跨停机时间补算运动；修复服务后需在编辑页明确重新保存配置恢复。没有真实设备指令出口。

## 面向交付人员的配置工作区

3D 编辑页中的点位配置采用独立工作区，按“选择数据源 → 选择数据 → 绑定部件 → 接入测试”四步组织，避免将全部配置堆进长弹窗。先选择来源，再配置要订阅的数据和 Topic，接着选择模型部件与动作，最后保存并验证已保存版本。姿态和模拟工序使用表单编辑：选择关键姿态或流程步骤，填写数值、目标点位和到位条件；完整 JSON 保留为高级入口，不要求用户编写 JSON 才能完成日常配置。

当前只有“平台模拟数据”可以驱动模型，通过平台 WebSocket 接收真实的模拟器反馈；Topic 按已保存配置自动订阅。API 轮询已有设备数据展示能力，但尚未接入这条运动链路；外部 WebSocket 地址、外部订阅报文和真实设备点位适配器也尚未实现。工作区明确将这两类来源标为暂不可选，不保存一个看似已接通、实际仍在使用模拟数据的来源选项。本轮不修改 `TwinDriveConfig` 契约，也不新增前端私有配置存储。

### 更换模型，保留配置

在部件绑定中可以把一个原模型的整组动作和碰撞部件重新映射到另一个模型。原模型按“实例 ID + 原资源 ID”区分，已删除实例或旧资源的失效引用仍会列出用于修复。名称唯一且同名的新部件仅作为可修改的预填建议；用户必须逐项确认并点击“应用到草稿”，之后再保存配置。未选择部件、节点重名、资源不匹配、重复驱动或不合法的父关节依赖都会阻止应用；不会跳过未匹配项或丢弃原配置。

正常更换顺序如下：

1. 保留旧模型，在场景中加入新模型，关闭新模型的原生动画（或关闭场景全局模型动画），先保存场景并等待部件加载。
2. 打开“数据与模型”工作区，在“更换模型，保留配置”中选择原模型和已保存的新模型，逐项选择对应部件，再应用到草稿。
3. 检查动作方向、轴心、范围和碰撞区域，保存点位配置并通过接入测试验证已保存版本。
4. 确认旧模型不再被动作或碰撞部件引用后，才可从场景移除旧模型并保存场景。

场景和点位配置分别保存、分别校验版本。服务端在保存场景时仍会检查已保存的全部绑定和碰撞引用，即使关闭数据驱动也不会解除这些引用；因此不能先删除旧模型或直接替换其资源，再依靠后续重绑使前一次场景保存成功。新旧模型短暂共存仍受现有模型数量、资源体积和网格预算约束，重绑功能不会绕过这些预算。

重绑仅替换目标的实例 ID、资源 ID 和稳定节点名，保留点位、Topic、绑定 ID、动作参数、父关节 ID、碰撞规则及工序。相同节点名不代表单位、坐标方向、轴心、零位或尺寸相同；新模型必须重新核对米制 / Y-up、运动轴与旋转中心、初始姿态、值换算、姿态关键点、行程范围和碰撞盒。父关节使用已配置的逻辑关系，不按新模型外形自动推断；资源根节点不能作为运动目标，运行层仍会校验实际节点与不可逆变换。应用草稿成功不等于动作已经校准或碰撞验收通过。

## 变换语义

坐标为模型资源坐标系：米制、Y 向上；旋转为 XYZ 欧拉角（度），轴必须归一化。模型实例的整体变换在外层独立应用。

- 平移：`T(axis × (value × scale + offset))`。
- 转动：`T(pivot) × R(axis, value × scale + offset) × T(-pivot)`。
- 姿态：按工程点值在用户配置的关键姿态之间插值位置和尺寸，四元数插值旋转。横轴是点位值而非时间；超出映射范围报错，不截断伪装成功。
- 关节依赖：`motion = parentMotion × ownMotion`。使用节点初始姿态时，`desired = motion × restModelMatrix`；显式校准零位时 `desired = motion`。不猜测任意模型的关节结构。
- 节点使用固定资源 ID + 唯一节点名称解析，禁止用遍历序号持久化。更换资源、重名、节点缺失、循环依赖及不可逆父级变换均显式报错。

## 配置、权限与通信

- `GET /api/v1/projects/{id}/twin-drive` 返回 `{projectId,revision,config,editable}`；`PUT` 提交 `{expectedRevision,config}`，独立于场景 revision。
- 文档保存在 PostgreSQL `twin_drive_documents`，V4 迁移；配置契约单一来源为 `shared/twin-drive.ts`，通过 `pnpm backend:contracts` 生成服务端结构校验。
- `/api/v1/twin-drive?projectId=…` 是独立 WebSocket。Cookie/Origin/租户/项目权限检查；观察者不能发送控制命令。hello 后发送 `{type:"subscribe",expectedRevision,topics:[...]}`，收到 subscribed 后消费 snapshot。订阅必须匹配该项目已保存的完整 topic 集合；配置变更需要重新订阅。topic 是本平台 WebSocket 的主题，不是已接入 MQTT Broker；仅允许 1–200 字符的字母、数字、点、下划线、冒号、斜线、连字符，不支持通配符、重复或跨项目订阅。样本同时包含 point ID 和 topic，前端验证两者映射。
- 仅旧手动模式支持带 `commandId` 和 `expectedRevision` 的 set/move/pause/resume/reset/run-procedure/stop-procedure 命令；ACK 仅代表命令受理，不代表机构已到位。自动模式统一拒绝这些命令，不能由任何预览连接篡改运行状态。
- 10 Hz 全量反馈含 sequence、配置版本、源时间和质量；浏览器配置版本不匹配时重新加载，乱序或异常数据不驱动模型。命令超时或断线不自动重发。
- 模拟状态在 Valkey，共享短租约和带令牌写入防止多个 API 重复积分；后台每 100 ms 执行，保存配置与推进共用项目锁，订阅者只读自动源最新态。每秒发现已启用的自动项目，上限 128，并在保存时使用数据库锁原子校验预算。命令有频率与去重预算，操作记录审计。可恢复运行态不等同于持久历史时序库。
- 自动模式的订阅、快照读取与手动命令拒绝不获取模拟器写租约，避免观察者和后台推进争用；仍通过数据库项目锁保持配置版本一致。连接关闭与发送竞争时必须清理该连接并记录上下文，不能中断其他观察者的发布。
- 每场景一个 renderer/循环；点位外部 store 不逐包进入 React，面板最多每 200 ms 更新。最多 128 点位/绑定、64 碰撞体、128 碰撞对、16 个工序（各 64 步）。

## 碰撞的准确边界

碰撞体是配置到节点上的简化定向长方体（OBB）。中心和尺寸在节点局部坐标；实际世界变换后做碰撞对检测，提供 enter/exit、规则 ID、严重程度和反馈序号，保留最近 100 个浏览器事件。剪切变换无法正确用 OBB 表示时明确报错。

这不是三角网格精确碰撞、连续碰撞检测、动力学或工业安全互锁。碰撞不会擅自修改观测点值或让模型偏离真实反馈；需要安全停机时应由工业控制侧的规则与授权命令实现。该碰撞检测与 Rapier 的静态第一人称行走分开；点位驱动开启时禁止使用静态行走世界。

## 长沙凯德校准案例

`scripts/configure-kaide-twin-drive.mjs` 默认只校准和生成私有预览文件，`--apply` 才通过授权 API 保存资产、关闭原生动画并写入点位配置；应用前备份场景/点位版本，不修改源 GLB 或上传限制。升级已有不同配置必须显式提供 `--expected-config <旧配置文件>`，服务端当前配置与其完全一致才允许 revision 校验写入，不覆盖用户后续编辑。

已配置 16 个独立点位、18 个控制器：六轴机械臂、双侧夹爪、四个托盘的米制路径距离、吊具升降/横移/双侧夹角、接收升降、激光状态。模型关节为同级节点，按显式轴心和依赖矩阵计算，不依靠模型动画时间。初始矩阵使用真实 GLB 做数值校验。碰撞演示配置四个托盘的代理盒及六个碰撞对。

每个点位显式保存 `kaide/<assetId>/<pointId>` 主题。默认后端连续空机构巡检流程让 J1 转动 6°、夹爪收拢、吊具横移 100 mm、空台上升 150 mm，然后等待反馈返回初始值再重复。其他点位仍持续发送反馈，但不冒充已配置自动搬运。原有三个手动验证工序保留为可选配置；故意碰撞流程不是默认自动工序。

四个 USB 物料和四个刻字节点的动态归属/交接尚未接入；当前不能称为完整自动生产流程。空夹爪和升降测试、显式托盘碰撞验证使用反馈条件推进，配置说明中公开限制。实际 PLC/OPC UA/MQTT 适配器、生产数据与模拟数据切换、持久碰撞历史、物料交接和生产安全互锁仍需后续实现。

## 验证

`pnpm test:twin-workspace` 使用隔离浏览器页面与拦截的 API fixture，检查 1366×768、1024×600 和 390×844 的浅/深主题、常驻保存按钮、底层场景挂载与交互隔离、跨步骤草稿、保存版本、非法数值、离开确认、只读和跨模型重绑。同时覆盖新建数据/绑定/碰撞部件、模拟流程、运动方式切换与姿态保护，以及高级 JSON 跨页保留和未应用时阻止保存。测试不连接真实设备、不修改项目数据；使用本机已安装的 Playwright 与 Chromium（分别可由 `PLAYWRIGHT_MODULE_PATH`、`CHROMIUM_EXECUTABLE` 指定），截图输出目录可由 `TWIN_WORKSPACE_SCREENSHOT_DIR` 指定。这是 UI 回归，不替代真实设备接入验收。

`pnpm test:twin-drive` 检查反馈控制、FK、过期/断线冻结、零缩放姿态、碰撞 enter/exit、异常整帧回滚和配置错误，并包含跨模型重绑的原子更新、配置保留、失效引用、资源隔离、重名、漏映射、重复驱动及父关节依赖回归；`node scripts/test-kaide-twin-drive.mjs` 检查真实案例零位及机构组合；`node scripts/test-kaide-twin-runtime.mjs` 将真实 GLB 的 2362 节点层级送入当前运行时，检查 18 个零位、32 个点位端点与碰撞（CPU 测试，不代表 GPU 验收）；`node scripts/test-twin-point-stream.mjs` 检查传输与命令生命周期。再执行 `pnpm test:scene-runtime`、前端 check/build、后端 Maven verify、契约 check 和本地 WebSocket/浏览器联调。

`node scripts/smoke-kaide-topic-stream.mjs` 默认仅输出测试计划；显式 `--run` 使用本地凭据连接 loopback，不修改配置、不发送启动/复位/目标命令。检查 topic、反馈变化、工序推进、多客户端一致、非法订阅及自动模式命令拒绝，关闭测试客户端后重连验证连续性；它不关闭用户浏览器，零观察者执行另有 Java 执行器回归。旧 `smoke-kaide-twin-websocket.mjs` 仅用于显式手动且无 topic 的历史配置，不应用于新的自动案例。

第一轮手动链路历史验收：长沙案例场景 revision 3 / 点位 revision 1，两个 Java 仓库各 57 项测试通过，两个客户端 114 组共同序列一致，并验证三个手动工序及浏览器碰撞。该轮复位并暂停的状态已由本轮独立后端模拟源方案替代，不代表当前运行模式。以上记录不是 GPU 性能达标、真实硬件接入或完整生产流程验收。

本轮同时补充了事务代理首次读取、同配置新版本切换、显式重新连接、异常整帧回滚、禁用和卸载清理回归。配置 revision 改变必须重建数据源/运行时序号边界；同一 revision 内的自动重连仍应拒绝序号倒退，禁止自动吞掉异常或重放命令。

本轮未运行通用 `backend:smoke`：它需要占用 8790，而该端口正由既有流体案例模拟源使用。未停止或替换该源；点位链路使用独立的本地 HTTP/WebSocket 验收脚本，不占用 8790。
