# 业务接口驱动模型（2026-10-09）

## 当前数据路径

`业务 REST / WebSocket → Java 后端采集 → 授权项目快照 → 模型部件动作`。

“模拟业务”指测试接口没有实际生产业务指向。接口由 Java 后端真实生成并通过 HTTP / WebSocket 输出；模型使用接口中的观测值。浏览器仅对已收到的有效观测终点做显示补间，不生成观测值、不预测后续运动。旧“平台模拟数据”执行器、初值/速度控制、Topic 和模拟工序不再作为新配置入口。

配置只需三步：

1. **连接接口**：选择 REST 轮询或 WebSocket 订阅，填写地址，检查接口并读取字段。
2. **绑定动作**：选择返回字段、场景中的模型部件、移动/转动/显隐/姿态和方向。旋转中心、单位换算等放在高级设置。
3. **检查效果**：启用并保存，订阅已保存版本，查看当前值和模型变化。草稿不会驱动模型。

编辑入口仍在 3D 编辑页的“数据与模型”。预览只接收反馈，不提供模拟启动、复位、目标命令或配置表。连接失败、数据过期或无效时，模型保留最后有效姿态并明确提示；开发者通过后端日志核对项目、配置版本、字段和采集失败原因。

## 可直接体验的业务案例

模板中心提供“接口驱动搬运单元 · 送检与回收”。点击会创建独立 3D 项目、模型和动作绑定，不修改已有项目。创建前逐字段检查真实测试接口，包括关节、车轮、夹爪和货物；旧接口只有小车位置与底座角度时拒绝创建。分步创建失败时显示已创建项目，可重试同一项目。检测到用户已修改项目则拒绝覆盖。

项目列表使用 `#/projects?type=2d|3d` 保留分类；刷新、回到项目和浏览器前进后退保持当前类型，3D 示例在 3D 分类中显示。窗口重新获得焦点或恢复可见时重取列表，避免另一页签创建的项目被旧缓存隐藏。失败使用已有通知及开发者日志，不显示假空列表。

后端提供同结构的两个接口：

- `GET /api/v1/test-business/handling-cell/state`：REST 当前状态。
- `WS /api/v1/test-business/handling-cell/live`：WebSocket 每 200 ms 推送。

两种协议共享后端 200 ms 采样时间，返回 `timestamp,sequence,scenario,geometryVersion` 和以下字段：

| 字段 | 对应运动或业务状态 |
| --- | --- |
| `agv.positionM,velocityMps,wheelAngleDeg` | 小车沿 Z 轴往返 4 m，四轮绕 X 轴滚动；轮角由实际行程与 0.16 m 半径计算，返回时反转 |
| `robot.baseYawDeg,shoulderDeg,elbowDeg,wristDeg` | 转台、肩、肘、腕联动；后端根据取放位置求解关节，腕保持夹爪竖直 |
| `robot.tcp.{xM,yM,zM}` | 夹持中心实际目标位置，供校验模型和后端坐标一致 |
| `gripper.openingM` | 0.56 m 张开、0.48 m 夹紧，与同宽工件匹配 |
| `cargo.{xM,yM,zM,yawDeg,attachment}` | 同一件工件全程可见；依次随车、随夹爪、停留检验台，再回到小车 |
| `cycle.{phaseCode,phase,elapsedMs,durationMs}` | 后端当前步骤与 64 秒周期位置，预览显示中文步骤，不用浏览器时间推测业务状态 |

64 秒流程：载货车到站 → 停稳 → 接近、夹取、抬升 → 转到检验台、下降、松开 → 机械臂收回 → 空车返回 → 检验 → 空车到站 → 夹取已检件、装回车 → 机械臂收回 → 成品返回。所有移动从静止平滑加速再减速；取放时车辆停稳，工件不复制造假、不在周期边界瞬移。检验是演示步骤，不代表真实检测结果。

独立静态资源 `builtin:handling-cell-v1` 包含稳定的车轮、各关节、夹爪和工件节点，关闭原生动画。`shared/handling-cell-geometry.json` 是尺寸、轴心、间隙、工位和阶段的单一事实源，生成 GLB 及 Java `/contracts/handling-cell-geometry.json` 资源。既有车间模型资源字节保持不变，不能通过修改旧 GLB 来影响已有客户项目。旧 `robot.angleDeg` 仍保留为兼容字段，新案例使用真实关节字段。

两个测试接口只提供无租户、无敏感信息的合成数据。配置可使用上述固定相对路径；后台映射至自己的固定 loopback 地址并发起实际 HTTP / WebSocket 请求，不能从请求 Host 推导采集地址。

接入真实业务时，替换接口地址和字段路径即可保留模型动作。外部服务必须在管理员设置的 `RUNTIME_ALLOWED_ORIGINS` 精确来源白名单中；现有白名单不自动扩大。WebSocket 的 `ws/wss` 使用对应 `http/https` 来源校验。需要鉴权头、复杂协议或 PLC 的业务源仍需服务端专用适配器，不能把密钥塞入地址或订阅 JSON。

## 接口和数据契约

- 单一配置契约为 `shared/twin-drive.ts`，由 `pnpm backend:contracts` 生成 Java JSON Schema。
- `GET /api/v1/projects/{id}/twin-drive` 返回独立配置 revision；`PUT` 使用 `{expectedRevision, config}`，与场景 revision 分开。
- `POST /api/v1/projects/{id}/twin-drive/test-source` 使用 `{connection}`，需要项目编辑权限；实际读取接口并返回 `{timestamp,fields:[{path,type,value}]}`，不保存整份响应。
- 新配置为 `source:"api"`，连接字段为 `protocol,url,timestampPath,intervalMs,timeoutMs`；WebSocket 可选 `subscribeMessage`。REST 间隔 200–60000 ms，超时 500–30000 ms。
- 数据字段 `sourcePath` 支持 `agv.positionM`、`items[0].value` 或 `$.agv.positionM`；禁止表达式、原型路径与超出 8 层的路径。动作字段只接受有限数值或布尔值（false/true 为 0/1）；缺失字段、类型不符或越量程明确报错。
- 点位可选 `valueLabels:[{value,label}]` 为离散业务状态提供中文名称，1–64 项，值为量程内唯一整数、名称为 1–120 个可读字符。预览仅显示后端实际反馈对应名称；未映射值显示未知状态，缺失、过期和断线分别提示，不生成或推进业务阶段。
- 接口采样时间必须来自配置的时间字段，是 ISO-8601 字符串；不使用收包时间冒充源时间。超出未来五分钟的源时间拒绝，过期值不驱动模型。
- 后端拒绝重定向，限制 256 KiB 响应、消息体和超时，WebSocket 订阅文本不超过 8192 字符。没有源数据时不制造零值或“正常”反馈。
- Java 后台独立发现并采集启用项目，不依赖浏览器连接。禁用、更改 revision、删除项目与关停服务清理相应采集连接。
- 浏览器仍使用 Cookie、精确 Origin、租户及项目权限检查的 `/api/v1/twin-drive?projectId=…` 网关；hello → subscribe（API 的 topics 为 []）→ subscribed → snapshot。上游私有 URL 和订阅报文不会发给观察者或公开分享：只读配置 `connection.url:""`、`redacted:true`，删除订阅报文，不能回写或测试该投影。两个固定公开测试端点保留相对地址，让预览明确标记“测试业务接口”。
- 快照为 `source:"api"`，带项目/配置版本、网关序号、源时间、质量、观测点值及 `procedure:null`。上游失败快照带安全错误说明和重试次数；模型冻结最后姿态。浏览器重连与上游采集重试分别计数，不能互相耗尽预算。
- 同一 revision 中序号回退明确阻断；配置变化和用户明确重连更新序号边界。重新连接不重放命令。

为兼容历史文档，点位结构仍保留 `assetId,metricKey,initialValue,maxSpeed`；新界面不要求设备登记、初值或最大速度，运行层不据此生成数据。历史 `source:"simulator"` 可读取并提示停用，不能保存为新配置，旧模拟命令返回 `410 legacy_simulation_removed`。点击“重新接入接口”仅建立空草稿，用户保存后才替换该项目配置；已有场景不改动。

## 模型变换和更换模型

运动使用模型资源坐标系，米制、Y-up；旋转值以度表示。平移按 `axis × (value × scale + offset)`；转动按配置轴心和单位轴；姿态曲线按数据值插值，越映射范围报错。节点使用稳定实例 ID、资源 ID 和唯一节点名，禁止以遍历序号持久化。资源根节点、重名、缺失节点、循环依赖、不可逆变换或原生动画冲突明确阻断。

### 平滑展示

REST 与 WebSocket 的采样频率通常低于浏览器渲染频率。每条有效新快照到达后，从当前显示姿态平滑移动到这条快照的实际观测终点，自动使用接收间隔作为时长，最多 1000 ms；无需新增配置。补间复用现有渲染循环和单调帧时钟，源时间继续用于过期与回退检查。

- 补间值限制在当前显示值与最新有效观测值之间，到达终点后保持，不外推；新快照从当前显示值重新衔接。
- 在数值层补间，逐帧重新计算动作与关节链，所有关节共用进度，不混合变换矩阵。显隐按最新快照立即更新。
- 开始补间前验证完整目标姿态与实际模型层级的可逆性；无效目标拒绝且不推进旧补间。实际写入失败时回滚整帧。
- 首帧、异常后恢复及源时间相同的修正直接应用实际终点。缺失、过期、断线、源错误或暂停取消补间，保持最后显示姿态并给出对应状态；不能以继续运动掩盖数据中断。

这是显示平滑，会使显示位置相对最新观测有短暂延迟，不代表新的源端测量值。业务字段、原始快照、质量与序号保持真实。

更换模型时，先保留旧模型，添加并保存新模型，再在“更换模型”映射全部动作与碰撞部件并保存配置，最后移除旧模型。字段路径、接口连接、动作 ID、参数、关节关系和碰撞规则保留。漏映射、歧义或资源变化不会静默丢弃配置；同名建议仍需用户确认坐标、单位、轴心和范围。

碰撞检查针对浏览器当前显示姿态（包括补间）的配置 OBB，输出 enter/exit，最多保留 100 条事件。事件保留最近源快照的序号与源时间用于追溯，源时间不是浏览器碰撞发生的精确时刻。该检查不是工业安全互锁，不能擅自修改接口反馈或实施真实设备控制。
