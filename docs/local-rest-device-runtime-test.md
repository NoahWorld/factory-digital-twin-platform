# 本地 REST 设备联动测试

本测试验证一条最小但真实可失败的链路：

```text
DEVICE-001 模拟设备
  → 服务端 REST 采集
  → 已保存的 JSON 字段映射
  → 资产 assetId
  → 3D 模型节点状态变色
  → 点击模型显示 2D 指标详情
  → HTTP 200 但数据时间戳过期时显示数据陈旧
  → REST 中断后明确显示失联与重连次数
```

这不是生产级数据网关。当前测试只执行 REST、只支持无凭据数据源，并限制为服务端环境变量显式允许的目标主机。WebSocket、凭据解析、集中调度和跨实例运行状态缓存仍待后续实现。

## 1. 启动三个本地进程

首次运行先安装依赖、应用本地 D1 迁移，并按 `README.md` 准备 `apps/api/.dev.vars` 中的初始化令牌。

终端一，启动只监听本机的模拟设备：

```bash
pnpm dev:mock
```

它会输出设备地址 `http://127.0.0.1:8790/device/DEVICE-001`，并为每个请求输出 JSON 日志。

在 `apps/api/.dev.vars` 中加入：

```dotenv
RUNTIME_POLLING_ENABLED=true
RUNTIME_ALLOWED_HOSTS=127.0.0.1:8790
```

终端二、三分别启动 API 和前端：

```bash
pnpm dev:api
```

```bash
pnpm dev:web
```

打开 `http://127.0.0.1:5173/`，登录后进入测试项目。

## 2. 配置一个模型资产

1. 在画布中只保留一个“3D 模型”组件，导入 GLB/自包含 GLTF。
2. 进入独立 3D 编辑器，在节点树中选中一个有唯一名称的设备节点。
3. 为它新建资产，填写 `assetId = DEVICE-001`，资产名称可填“模拟设备 001”。
4. 保存并返回画布。

当前本地竖切要求画布恰好包含一个 3D 组件，并且最多轮询 50 个已映射资产；超过边界会显示明确配置错误。

## 3. 配置 REST 数据源

从画布工具栏打开“数据源”，新建：

| 配置项 | 值 |
| --- | --- |
| 名称 | 本地模拟设备 |
| 类型 | REST 轮询 |
| URL | `http://127.0.0.1:8790/device/DEVICE-001` |
| 轮询周期 | `2` 秒 |
| 请求超时 | `1500` 毫秒 |
| 数据时间戳路径 | `$.timestamp` |
| 凭据引用 | 留空 |

数据时间戳路径可留空以兼容暂时不提供时间戳的接口，但此时只能识别请求失败，无法识别“接口仍返回 200、设备数据却停止更新”。配置路径后，路径必须解析为 ISO 兼容字符串；超过同一数据源映射中最短的“数据过期”时间会返回 `data_source_stale`。如果主机不在 `RUNTIME_ALLOWED_HOSTS`、响应超时、HTTP 非 2xx、响应超过 256 KiB 或不是合法 JSON，API 也会返回各自的错误码并记录 `requestId`。

保存后点击“测试连接并发现字段”。成功结果应显示请求耗时、响应大小、采集时间、源时间戳，以及 `$.deviceId`、`$.values.status`、`$.values.temperature` 等标量路径、类型和样例。测试不会保存整份响应：最多返回 200 个标量字段，递归深度最多 8 层，每个数组只检查前 10 项；超过边界时界面会明确标记结果已截断。未保存修改时必须先保存，WebSocket 测试目前会明确显示尚未开放。

## 4. 配置字段映射

回到独立 3D 编辑器，选中 `DEVICE-001` 对应的模型节点，在“资产指标映射”中为同一个数据源新增四行：

| metricKey | JSON 字段路径 | 类型 | 单位 | 数据过期 |
| --- | --- | --- | --- | --- |
| `status` | `$.values.status` | 字符串 | 留空 | `6` 秒 |
| `temperature` | `$.values.temperature` | 数值 | `°C` | `6` 秒 |
| `pressure` | `$.values.pressure` | 数值 | `kPa` | `6` 秒 |
| `alarmLevel` | `$.values.alarmLevel` | 数值 | 留空 | `6` 秒 |

路径不存在或返回值类型不符时，采集会失败并明确显示为失联，不会用默认值伪装正常。

## 5. 验证状态、详情和失联

进入画布“预览”。初始数据为 `running`，模型节点应显示绿色；顶部显示在线。点击已绑定的模型对象，应打开 2D 设备详情，并看到状态、温度、压力、字段路径和最近成功时间。

切换为预警：

```bash
curl -fsS -X POST http://127.0.0.1:8790/control/state \
  -H 'content-type: application/json' \
  --data '{"status":"warning"}'
```

下一次轮询后节点应变黄。把 `warning` 改为 `alarm`、`stopped` 或 `running`，可分别验证红色、灰色和绿色。

模拟 HTTP 正常但数据时间戳陈旧：

```bash
curl -fsS -X POST http://127.0.0.1:8790/control/stale
```

接口仍返回 HTTP 200，但时间戳固定在 30 秒前。下一次轮询后预览必须显示“数据陈旧”和重连次数，模型节点变为半透明灰色；恢复新鲜时间戳：

```bash
curl -fsS -X POST http://127.0.0.1:8790/control/fresh
```

模拟数据中断：

```bash
curl -fsS -X POST http://127.0.0.1:8790/control/outage
```

下一次轮询会收到 HTTP 503。预览顶部必须显示“数据失联”和当前重连次数，模型节点变为半透明灰色；已打开的 2D 详情显示错误原因，并把旧指标标为“最后一次成功值”，不能把它表述为当前实时值。

恢复设备：

```bash
curl -fsS -X POST http://127.0.0.1:8790/control/recover
```

下一次成功轮询后，重连次数归零，在线状态、3D 颜色和 2D 指标恢复更新。

## 6. 通过标准

- REST 正常时，温度和压力会随轮询变化，API 与模拟设备终端都有请求日志。
- 已保存 REST 数据源的连接测试能发现预期字段；设备中断时测试必须返回明确错误和 `requestId`，不能显示假成功。
- `status` 或 `alarmLevel` 变化后，已绑定的模型节点按规则变色。
- 只有点中已映射对象或其子对象才打开对应 2D 详情；未映射对象显示明确提示。
- 接口返回 200 但源时间戳超过 `staleAfterSeconds` 时必须显示“数据陈旧”，不能继续显示在线。
- 中断后不得保持“在线”或继续把最后值冒充实时值；必须显示失联、错误和重连次数。
- 恢复后应自动回到在线，不需要刷新页面。

如需在独立临时 D1 上自动验证服务端链路，可启动一个使用临时 `--persist-to` 目录、监听 8791 端口的 Worker，然后运行：

```bash
pnpm smoke:runtime -- http://127.0.0.1:8791 <该临时 Worker 的初始化令牌>
```

脚本只接受 `localhost`/`127.0.0.1` 的 Worker 地址。它会在临时数据库中按该临时令牌派生测试账号并创建测试项目，代码生成一个带固定节点名 `SmokeDeviceNode` 的自包含 GLTF 测试设备，上传并绑定到 3D 画布，再配置资产、REST 源、源时间戳路径和四个字段映射。自动检查覆盖连接测试、字段发现、连接失败上下文、运行、预警、HTTP 200 时间戳陈旧、恢复新鲜时间戳、503 中断、错误 `requestId`、模型上传和画布绑定；默认最后删除测试项目，因此同一个隔离环境可以重复执行。不要把真实初始化令牌写入脚本或提交 Git。

如需保留隔离测试项目做浏览器视觉验收，可追加 `--keep-project`。脚本会输出预览地址；验收结束后直接删除临时 `--persist-to` 目录即可，不要在正式 D1 上运行保留模式：

```bash
pnpm smoke:runtime -- http://127.0.0.1:8791 <该临时 Worker 的初始化令牌> --keep-project
```
