# 2D / 3D 联动交互

## 配置与使用

3D 场景属性关联一个 2D 项目后，3D 预览读取其已保存画布并透明叠加。保持 1920 × 1080 坐标比例，非全屏等比适配；空白区域不截获 3D 鼠标操作。2D 内已有的 3D 节点不叠加，防止递归引用或重复加载模型。2D 全屏按钮对包含场景和叠加画布的整体生效。

选中 3D 交互模型，在“交互事件”编辑点击动作；选中 2D 组件，在属性栏编辑同一套点击动作。一个点击可按顺序配置最多 8 个动作：

| 动作 | 配置目标 | 运行效果 |
| --- | --- | --- |
| 文字提示 | 标题、纯文本内容 | 可关闭的消息弹窗，不执行 HTML 或脚本 |
| 设备详情 | 稳定 `assetId` | 当前设备数据组件更新；未配置详情组件时显示详情浮层 |
| 面板显隐 | 一个纯 2D 组件、显示/隐藏/切换 | 仅本次预览改变显隐，不代表分组/嵌套 |
| 聚焦模型 | 3D 项目及稳定实例 ID | 复用现有相机定位可见模型，保留禁止底部查看限制 |
| 更新文本 | 一个纯文本组件、内容 | 仅本次预览替换文字 |

2D 组件可设“预览时初始隐藏”，随后由模型或其他组件显示。编辑态始终保留组件以便配置。可通过属性栏链接进入关联 2D 或源 3D 编辑页；两边必须分别保存。

## 契约与边界

唯一类型与结构解析入口是 `shared/twin-actions.ts`。2D 节点 `interaction` 包含 `clickActions` 和 `hiddenInPreview`；3D 实例 `clickActions` 可缺失。仅缺失时兼容旧模型点击选择绑定资产，显式空数组关闭默认行为。

保存前服务端按补丁合并后的完整文档校验：设备须属于所属/关联 2D；面板须为真实纯 2D 节点；更新文本目标须为 `plain-text`；模型须在允许的 3D 项目中存在。3D 模型动作的聚焦目标限当前场景，2D 可选关联或已引用、且当前账号可读的场景。无权限、未知字段、无效类型和悬空引用均拒绝，不返回假成功。删除被动作引用的组件/实例前先移除对应动作。

运行端先校验整批目标，再修改临时状态。消息、显隐、内容、选择和相机不自动写回项目；重开/切换文档修订后恢复保存配置。真实加载失败、资产错误与采集断线保持可见。

同页和同源已打开页签通过版本化项目定向事件同步。事件包含 origin/target、相关 ID、时间戳；只处理授权关联来源，限定 5 分钟，按单个接收项目持有有界去重缓存。发送方先本地执行，接收方不再广播；模型聚焦按目标项目单独拆包。跨项目聚焦需要目标预览已打开，或目标已嵌入 2D；没有远端执行回执，不自动新建浏览器页签。这是页面交互同步，不是跨用户消息服务，也不是控制真实设备。

## 性能与验证

- 透明叠加复用 DOM 画布，不新建 WebGL renderer，不再次下载 3D 模型。
- 目标目录只读取有权限的场景配置，最多 3 个并发，不加载 GLB。相机聚焦复用既有渲染循环与资源。
- 运行时消息队列上限 32；事件相关 ID 与目标缓存均有界。设备采集沿用现有 50 台预算及错误状态。
- Worker 新增 `0022_twin_actions.sql`；Java JSONB 无需额外表字段迁移，schema 由 `pnpm backend:contracts` 生成。
- 回归命令：`pnpm test:twin-actions`、`pnpm test:linked-canvas`、`pnpm test:scene-runtime`、`pnpm test:standalone-3d`、`pnpm test:composable-dashboard`、`pnpm test:runtime-ui`、`pnpm test:ui-theme`、`pnpm check`、`pnpm build`，及 Java 契约、单元和本地 API 验证。

### 本地 Java API 冒烟测试

在仓库根目录执行，前提是已部署最新 Java 构建、本机 Docker Compose 和 `http://127.0.0.1:18080` API 可用，以及已初始化 `deploy/local/.local/admin.json`。脚本仅使用该本地地址，读取管理员文件用于登录但不输出凭据；不启动模拟源，不占用 8790，也不修改已有业务项目。

```bash
pnpm backend:smoke:twin-actions
```

测试通过正式 API 创建独立的临时 2D/3D 项目、业务资产及权限测试账号，验证五类动作的保存与读取、旧字段缺失和显式空动作的区别、未知/超限动作拒绝、悬空目标与解除关联的原子拒绝、源项目编辑权限及目标项目读取权限。默认无论成功或失败，都会尝试清理本轮临时数据；清理错误会明确报错并保留尚未清理项目的记录，不报告假成功。

需要继续浏览器验收时，成功后保留临时配置：

```bash
pnpm backend:smoke:twin-actions --keep-fixture
```

输出包含临时场景和画布 ID，可用现有前端进入对应预览。场景中的单个模型和 2D 联动按钮配置了文字消息、面板显示、文本更新、设备详情与模型聚焦；画布还包含全屏按钮。`--keep-fixture` 只在全部 API 检查成功时保留，失败仍执行清理。API 通过不代表浏览器交互已验收，应另外检查透明叠加、点击、全屏及跨页联动。

浏览器验证完毕后单独清理，不要手动改名或删除临时项目：

```bash
pnpm backend:smoke:twin-actions --cleanup
```

临时记录保存在已忽略的 `deploy/local/.local/twin-action-smoke.json`，包含本轮唯一标识、项目 ID/名称和账号 ID/登录名，不含密码或 Cookie。清理按记录核对 ID 与名称后调用项目删除 API，再通过本地 PostgreSQL 精确删除本轮测试账号，并输出逐项结果；不会清空数据库或其他项目。只有全部清理完成才删除记录。已有记录时脚本拒绝新建测试，须先完成 `--cleanup`；不要删除记录文件来跳过未完成的清理。
