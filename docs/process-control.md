# 管路编辑与状态联动

2D 画布的工艺管路支持自由端点、连接设备四边锚点、水平/垂直正交布线和最多 32 个途经点。端点和途经点可拖动，也可用方向键移动；连接设备移动或缩放后管路随之更新。保存校验最终画布引用，删除设备前须重新连接或删除关联管路。

组件及 3D 流体可保存 `stateBinding`。每项绑定声明通用点位名称、number/string/boolean 类型、1–86400 秒过期时间与 1–8 条有序规则；规则按第一条匹配，数值支持大小比较，布尔和文本仅等值。可切换颜色、显隐、流动启停、方向与视觉速度（0–30，0 停止）。3D 使用既有流体编辑和渲染，不自动把 2D 管路转成 3D。

独立版 `main` 沿用可选 `kingdom.iot.points` v1 宿主 `postMessage` 协议。点位名称为 1–200 个 UTF-16 单元，禁止首尾空白和控制字符，不要求设备 ID / 属性 ID。宿主必须以 `iotEmbed=1&parentOrigin=精确HTTP(S)来源` 嵌入；URL 查询位于 hash 路由之前。浏览器校验父窗口、精确 origin、消息版本和会话；不传递凭据。

同一 iframe 的 2D 画布、独立 3D 流体、关联 2D 看板和内嵌 3D 场景共用一次握手与点位清单。清单合并数值绑定和状态绑定，同名点位类型必须一致，采用最短过期时间，总计最多 500 个不同点位。场景加载或移除后重新握手，旧会话数据立即失效。普通预览、固定发布和关联看板共用这条链路；未启用宿主或缺失点位时显示错误，不伪造运行数据。

缺值、质量异常、过期、源时间异常、类型冲突、未匹配规则或连接错误会显示诊断并停止流动；运行态投影不写回配置。已有资产、业务数据接口和 twin drive 链路保持独立。本功能提供展示联动，不执行设备控制或工艺仿真。

持久化由独立 Java 后端校验生成契约、点位规则和管路引用。历史 Worker 对新增配置明确拒绝写入，不能忽略后报成功。

验证入口：`pnpm test:process-control`、`pnpm test:iot-embed`、`pnpm test:scene-runtime`、`pnpm check`、`pnpm build`；配套后端运行 `mvn -B verify` 与契约快照检查。宿主真实点位仍需在客户环境核对名称、类型、质量及源时间。
